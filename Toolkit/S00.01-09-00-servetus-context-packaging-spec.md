# Servetus Context Packaging Spec

## Purpose

This spec defines how context is assembled, filtered, and packaged before being
sent to any LLM endpoint. The LLM receives a pre-resolved, minimal context object.
It does not orient itself — the packaging layer orients it.

**The core principle:** Orientation is infrastructure. Reasoning is LLM.

---

## The Three Laws of Awareness (Source)

This spec is the operational implementation of the three laws:

1. **Know what's available.** — The script layer collects from all registers.
2. **Know how to receive it.** — The orient layer places it in context.
3. **Know what to do with it after you've got it.** — The packaging layer
   delivers only what the query requires, to the endpoint that can handle it.

*Origin: V.P. Wierwille. Filed in `Library/wierwille-vpw/` when available.*

## The Four-Layer Stack

```
┌─────────────────────────────────────────┐
│  1. SCRIPT LAYER                        │  ← No LLM. Deterministic.
│     Read all registers. Collect raw     │    Fast. Offline-capable.
│     data from known sources.            │    50-75% of daily ops live here.
├─────────────────────────────────────────┤
│  2. ORIENT LAYER                        │  ← No LLM. Rules-based.
│     Discover → Orient → Plan            │    Apply disclosure rules.
│     Who is speaking? What channel?      │    Resolve identity and circle.
│     What arc? What posture?             │    Filter by need.
├─────────────────────────────────────────┤
│  3. PACKAGE LAYER                       │  ← No LLM. Assembles the object.
│     Assemble minimal context object.    │    Enforces trust tiers.
│     Apply anonymization if endpoint     │    Logs what was sent.
│     is untrusted. Audit trail here.     │
├─────────────────────────────────────────┤
│  4. LLM LAYER                           │  ← LLM enters here. Only here.
│     Receives package. Reasons.          │    Endpoint is configurable.
│     Responds. Does not pull from        │    Model is swappable.
│     vault directly.                     │
└─────────────────────────────────────────┘
```

## Layer 1 — Script Layer

Reads all known registers. No LLM involvement.

| Register | What it provides |
|----------|-----------------|
| `hopper-events.log` vs cursor | New arrivals since last check |
| `06-Radar/open-loops.md` | What's waiting on action |
| `10-System/last-session-brief.md` | Prior session state |
| `08-Witnesses/<actor>.md` | Known person data |
| `config/talk-rooms.json` | Room → circle mapping |
| `config/talk-cursor.json` | Unread Talk messages |
| `config/clients/<name>/` | Client profile when in client context |
| Calendar API | Upcoming events |
| `06-Radar/` items | Active radar, overdue items |
| `10-System/dev-backlog/` | System development status |

Output: raw structured data object. Not yet filtered. Not yet packaged.

## Layer 2 — Orient Layer

Places the raw data in context. Rules-based, no LLM.

### The Situational Awareness Cycle

**Discover**
Orient to the person first. Who are they? What channel? What do I know about them?
The person unlocks the context. The context reveals the operational picture.
If the person is not on the radar — talking to Servetus puts them there.

**Orient**
Place the information. What arc does this touch? What is the current posture —
what's the relationship, what's active, what's the history?
This is *how* the data sits within everything else.

**Plan**
Determine what to do with what you have before acting.
If no plan exists, determine one. Don't surface without purpose.
Don't act without a plan.

**Route**
Execute directly or delegate to the appropriate specialist agent.
The XO never pretends to be an expert it isn't.

### Identity Resolution

1. Extract actor ID from message or channel
2. Look up `08-Witnesses/<actor>.md` — get circle, relationship context, parameters
3. Look up room in `config/talk-rooms.json` — get room circle
4. **Effective circle = most restrictive of room circle and requester circle**
5. If actor unknown → treat as `public`

## Layer 3 — Package Layer

Assembles the minimal context object for this specific query.
Applies disclosure rules. Logs everything sent.

### What Enters a Package

| Data | Included when | Notes |
|------|--------------|-------|
| Room/channel identity | Always | Determines circle baseline |
| Requester identity (resolved) | Always | Circle assigned |
| Effective circle | Always | Most restrictive tier |
| Query text | Always | The actual question |
| Relevant arc summary | Query touches an arc | Summary only — not full file |
| Witness parameters | Person relevant to query | See trust rules below |
| Open loops | Operational/planning query | Filtered to circle |
| Hopper items | Query about new arrivals | |
| Radar items | Situational query | |
| Client profile data | In client context, circle permits | Scoped to that client only |

### What Never Enters a Package

- Sovereign-tier personal assessments (Christian's private read on a person)
- Cross-client data (Binary Ranch data never in a First Century package)
- Raw credentials or tokens of any kind
- Full vault dumps or unfiltered file contents
- Another person's witness file unless directly relevant and circle permits
- Data above the effective circle level

### Witness Data — Trusted vs. Untrusted Endpoints

**Trusted endpoint (self-hosted, sovereign):**
Send witness data in natural language as written.
Full nuance, full weight, full relationship context.

**Untrusted endpoint (third-party API):**
Anonymize identifiers — names, companies, project titles replaced with variables.
Abstract relational weight — `PERSON_B: style=direct, last_interaction=tense, urgency=high`
Sovereign assessment never sent regardless of trust level.

*The goal of self-hosting is to trust the endpoint with the real data.
Anonymization is a fallback for untrusted endpoints, not the default mode.*

## Layer 4 — LLM Layer

The endpoint receives the package and reasons on it.
It does not pull from the vault. It does not know what was withheld.

### Endpoint Configuration

```json
{
  "reasoning_endpoint": "https://api.anthropic.com",
  "synthesis_endpoint": "http://localhost:11434",
  "model_reasoning": "claude-sonnet-4-6",
  "model_synthesis": "llama3.2",
  "trusted": true
}
```

**`trusted: true`** → full natural language context, named entities
**`trusted: false`** → anonymized identifiers, abstracted relational weight

### Model Escalation Path

```
Script output     → no LLM
Synthesis/brief   → local model (Haiku or self-hosted equivalent)
Reasoning/response → configurable frontier model
```

Use the cheapest model that can do the job. Escalate only when necessary.
The endpoint and model are swappable per deployment without architectural change.

## Audit Trail

Every package sent must produce an audit log entry:

```
timestamp        | ISO 8601
actor_id         | who asked
room_token       | which channel
effective_circle | resolved circle
layers_included  | which data layers entered the package
layers_excluded  | which were excluded and why
endpoint         | which model/endpoint received it
anonymized       | true/false
```

Log location: `10-System/package-audit.log`
Sovereign tier only. Never committed to Git. Never shared.

---

## Security Properties

This layer is the primary defense against:

**Prompt injection** — Talk message content cannot reach vault data it was
never packaged with. Malicious instructions in a message are just query text.

**Cross-client leakage** — Client A data is never packaged for a Client B context.
The orient layer resolves which client profile is active before packaging begins.

**Credential exposure** — Credentials never enter a package. Period.

**Over-disclosure** — Effective circle is computed before packaging.
Anything above that circle is excluded regardless of query content.

## Deployment Variance

Different deployments configure different endpoints and trust levels:

| Deployment | Reasoning | Synthesis | Trust |
|-----------|-----------|-----------|-------|
| Local Claude Code | Anthropic API | Anthropic API | trusted |
| Binary Ranch server | Anthropic API | Local Ollama | trusted |
| Ministry deployment | Local model | Local model | trusted |
| Public-facing bot | Anthropic API | Anthropic API | untrusted |

The packaging layer adapts. The vault and specs do not change.
