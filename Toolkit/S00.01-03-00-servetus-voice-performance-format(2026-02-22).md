# Servetus Voice Performance Format (SVP)

## Purpose

Plain text loses the performance of speech. When you transcribe voice to text, you lose:
- **Pacing** — how fast or slow someone speaks
- **Pauses** — deliberate silence, hesitation, contemplation
- **Emphasis** — which words carry weight
- **Pitch** — rising questions, falling statements, emotional contour
- **Energy** — volume, intensity, conviction
- **Emotion** — detectable affect in the voice
- **Interruptions** — false starts, self-corrections, trailing off

LLMs receive flat text and cannot distinguish between a whispered confession and a shouted command. They cannot hear a long pause that means "I'm reconsidering everything I just said." They cannot detect the rising pitch of uncertainty or the falling energy of resignation.

SVP encodes this information alongside the transcript in a human-readable, machine-parseable format — like an SRT file for the soul of speech.

## Design Principles

1. **Human-readable first** — You can read an SVP file like a screenplay with stage directions
2. **Machine-parseable** — Any LLM or script can extract structured prosodic data
3. **Paired with audio** — SVP is a companion to the source audio, never a replacement
4. **Measurable where possible** — Use real values from audio analysis, not guesses
5. **Gracefully degradable** — A minimal SVP with just timestamps and text is still useful

## File Extension

`.svp` — Servetus Voice Performance

## Format Specification

### Header Block

```
#SVP v1
#source: voice_20260222_1430.wav
#model: whisper-large-v3
#prosody_engine: servetus-voice/0.1.0
#analyzed: 2026-02-22T14:35:00-06:00
#duration: 45.2s
#speaker: Christian Sass
```

Lines beginning with `#` in the header are metadata. Required fields:
- `#SVP v1` — format version (must be first line)
- `#source` — filename of the source audio
- `#duration` — total audio duration

Optional fields:
- `#model` — transcription model used
- `#prosody_engine` — software that generated the prosodic analysis
- `#analyzed` — ISO-8601 timestamp of analysis
- `#speaker` — speaker identity if known

### Segment Block

A segment is a continuous stretch of speech. Format:

```
@segment <id> [<start> → <end>]
| pace: <wpm> | volume: <level> | pitch: <contour> |
| emotion: <label> | confidence: <0.00-1.00> |
"Transcribed text exactly as spoken."
```

**Fields:**
- `id` — sequential integer starting at 1
- `start` / `end` — timestamps in `HH:MM:SS.mmm` format
- `pace` — words per minute for this segment (integer)
- `volume` — `whisper` | `quiet` | `moderate` | `loud` | `shouting`
- `pitch` — `low-flat` | `low-rising` | `mid-flat` | `mid-rising` | `mid-falling` | `high-flat` | `high-rising` | `high-falling`
- `emotion` — detected affect: `neutral` | `contemplative` | `excited` | `frustrated` | `amused` | `emphatic` | `uncertain` | `resigned` | `passionate`
- `confidence` — Whisper's transcription confidence for this segment

### Pause Block

A pause is a gap between segments. Format:

```
@pause [<start> → <end>] <duration_ms>ms <type>
```

**Pause types:**
- `breath` — natural breathing pause (< 300ms)
- `deliberate` — intentional pause for emphasis or thought (300ms–1500ms)
- `long` — extended silence suggesting deep thought or topic shift (> 1500ms)
- `hesitation` — filled pause with um/uh/er
- `interruption` — speaker stops mid-thought

### Emphasis Markers

Within the quoted text, emphasis is marked with `*`:

```
"This is *exactly* what I mean."
```

Word-level timestamps (when available from Whisper) can be encoded:

```
@words [00:00:01.200 → 00:00:03.450]
"This"[1.200] "is"[1.450] "*exactly*"[1.680] "what"[2.100] "I"[2.340] "mean."[2.500]
```

### Topic Break

When a topic shift is detected (long pause + content change):

```
@break [<timestamp>] ---- <label>
```

Example:
```
@break [00:01:23.000] ---- shifting to sovereignty discussion
```

## Complete Example

```
#SVP v1
#source: voice_20260222_1430.wav
#model: whisper-large-v3
#prosody_engine: servetus-voice/0.1.0
#analyzed: 2026-02-22T14:35:00-06:00
#duration: 12.8s
#speaker: Christian Sass

@segment 1 [00:00:00.000 → 00:00:02.340]
| pace: 120 | volume: moderate | pitch: mid-falling |
| emotion: contemplative | confidence: 0.94 |
"So the bigger question is,"

@pause [00:00:02.340 → 00:00:02.780] 440ms deliberate

@segment 2 [00:00:02.780 → 00:00:05.900]
| pace: 145 | volume: moderate | pitch: mid-rising |
| emotion: uncertain | confidence: 0.91 |
"is this something I should be *trusting*?"

@pause [00:00:05.900 → 00:00:06.800] 900ms deliberate

@break [00:00:06.800] ---- resolution

@segment 3 [00:00:06.800 → 00:00:10.200]
| pace: 155 | volume: loud | pitch: mid-flat |
| emotion: emphatic | confidence: 0.96 |
"Or should I be building my *own* local alternative."

@pause [00:00:10.200 → 00:00:10.600] 400ms breath

@segment 4 [00:00:10.600 → 00:00:12.800]
| pace: 130 | volume: moderate | pitch: low-falling |
| emotion: contemplative | confidence: 0.93 |
"Can I achieve the same results locally?"
```

## Reading an SVP File

An SVP file reads like a script. You can scan it and immediately understand:
- What was said (the quoted text)
- How it was said (the prosodic annotations)
- The rhythm of the conversation (pauses and breaks)
- Where the speaker's energy and conviction shifted

An LLM consuming an SVP file gets dramatically more context than flat text. It can:
- Detect uncertainty and ask clarifying questions
- Recognize emphasis and weight those words more heavily
- Understand that a long pause after a statement may indicate doubt
- Respond to the emotional register, not just the semantic content

```yaml
    time_end: 2026-02-22T14:30:12-06:00
    coverage: full
  - path: "[[voice_20260222_1430.svp]]"
    type: voice-performance
    device: "servetus-voice"
    derived_from: "[[voice_20260222_1430.wav]]"
    coverage: full
```

The audio is the ground truth. The SVP is the human-readable translation layer. Both are filed. Both are verifiable.
