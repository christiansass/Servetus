# Servetus Session Start Protocol

Sequence the engine follows at the start of every session, before any user
interaction is processed.

---

## Step 1 — Read the Last Session Brief (AUTO, SILENT)

Check if `10-System/last-session-brief.md` exists. If it does, read it.
It contains the closing exchange and metadata from the prior session — the
short-term memory layer that cures amnesia between sessions.

- Do NOT announce that you are reading it
- Do NOT summarize it back to the user
- Orient silently and be ready to continue where things left off
- If the user asks "where were we?" — answer from this file

---

## Step 2 — Inbox / Hopper Check (AUTO, SILENT)

Read `10-System/hopper-events.log` and compare against `10-System/hopper-cursor.txt`.
Surface any new arrivals naturally, not as a system alert. See behavioral rules for
full hopper protocol: `Toolkit/S00.01-04-00-servetus-behavioral-rules.md`

---

## Step 3 — Confirm Toolkit Loaded

Timezone: `America/Chicago`
Specs active: bootloader → export rules → frontmatter schema → time rules →
spelling rules → topic segmentation → sorting → vault search → behavioral rules → guardrails

---

## Inbox / Hopper Triage (AUTO-TRIGGER — no prompt needed)

When the user says anything resembling these — run `inbox-triage.py` immediately,
without asking clarifying questions first:

| Trigger phrase family | Examples |
|---|---|
| Check the hopper/inbox | "check the hopper", "check the inbox", "what's in the inbox" |
| New evidence | "I have new evidence", "any new evidence", "new files came in" |
| Scan/triage | "scan inbox", "triage", "what came in", "what's new" |
| Loose phrasing | "anything new", "what do we have", "look at the inbox" |

**Run:**
```bash
python3 10-System/inbox-triage.py
```

**Then:**
1. Present the numbered triage list exactly as output by the script
2. For each item, offer the suggested actions from the script
3. If an arc match is shown — confirm it before filing
4. If no arc match — offer the top 2–3 active arcs as candidates, or "new arc"
5. Wait for the user to pick a number, describe an action, or say skip

After the user responds: execute, move to next item. At end: summarize what was
filed where. This is an automation loop, not a Q&A.
