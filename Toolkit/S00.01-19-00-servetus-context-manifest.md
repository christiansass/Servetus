# Servetus Context Manifest

## Purpose

The context manifest is the primary context entry point for every session. It
is a short, human-readable prose document — written in natural sentences — where
every key entity (arc, project, person, concept, place) is wrapped in `[[brackets]]`.

The brackets are not decoration. They signal: *a file exists for this term and
can be fetched if the conversation needs it.*

The manifest replaces full file injection. The engine loads the manifest (~200
tokens), not the files it references. Files are pulled on demand, only when the
conversation actually touches that topic.

---

## Format

### Location

```
10-System/context-manifest.md
```

### Structure

Free prose, written by the human. No required sections. The only rule: every
entity worth knowing about gets brackets.

```markdown
We're building [[Servetus]] as a memory architecture for [[Christian Sass]],
currently focused on [[BinaryRanch]] infrastructure and the [[SevenTalents]]
platform. [[Alicia Andes]] is the lead contact on [[Agua Bee]]. [[Evan]]
starts onboarding next month alongside [[Josh]].

The [[Two-Agent Architecture]] is in active development. [[StoryMap]] is
in arc status, waiting on [[Servetus Talk Pipeline]] to stabilize first.
[[Mary Ann Peter]] situation is unresolved — monitoring only.

Open questions: [[Control Room Spec]], [[OpenClaw]] competitive position,
[[T-Mobile Breach]] resolution timeline.
```

The document reads as plain English. The brackets are invisible to a human
reader who knows the context. To the engine they are a pull list.

---

## Resolution Rules

When the engine encounters `[[term]]`, it resolves as follows:

### Match order (first match wins)

1. **Frontmatter `title:`** — case-insensitive exact match after stripping
   type suffixes (`Arc`, `Project`, `Spec`, `.me`, `.md`)
2. **Frontmatter `slug:`** — exact match
3. **Frontmatter `aliases:`** — any listed alias
4. **Filename stem** — slugify the term (lowercase, spaces→dashes,
   strip type suffixes), match against filename stem

### Normalization rules

| Input | Normalized |
|-------|-----------|
| `[[BinaryRanch]]` | `binaryranch` |
| `[[Binary Ranch]]` | `binary-ranch` |
| `[[binary ranch]]` | `binary-ranch` |
| `[[StoryMap]]` | `storymap` |
| `[[StoryMap.me]]` | `storymap` (strip TLD) |
| `[[Seven Talents Arc]]` | `seven-talents` (strip type suffix) |
| `[[Alicia Andes]]` | `alicia-andes` |
| `[[OpenClaw]]` | matches "OpenClaw — Competitor Intelligence Arc" ✓ |

Spaces, dashes, and underscores are equivalent. Case is ignored.

**Em-dash rule:** strip `—` and everything after it from the title before
matching. "OpenClaw — Competitor Intelligence Arc" becomes "OpenClaw" for
resolution purposes. The description after `—` is metadata, not the name.

Type suffixes stripped before matching: `Arc`, `Project`, `Spec`, `Profile`,
`Series`, `Pipeline`, `Service`, `Tool`, `.md`, TLDs (`.me`, `.com`, etc.).

### Ambiguity

If two files match the same normalized term, surface once:
> *"[[Term]] matched both X and Y — which should I use?"*

After the user confirms, record the preferred match in `config/overrides.md`.

## Stub Creation

If `[[term]]` resolves to nothing, the engine creates a stub automatically and
flags it once:

> *"No file found for [[Agua Bee Phase 2]] — created stub at `05-Arcs/agua-bee-phase-2_arc.md`."*

### Stub format

```markdown
---
servitus:
  schema_version: 2
  record_type: stub
  status: stub
identity:
  title: "Agua Bee Phase 2"
  slug: "agua-bee-phase-2"
time:
  created_at: "2026-04-10T00:00:00-05:00"
---

# Agua Bee Phase 2

*Stub — created from context manifest reference on 2026-04-10. Fill when ready.*
```

### Stub placement

| Link context | Default location |
|-------------|-----------------|
| Person name | `05-Arcs/<slug>_arc.md` |
| Project noun | `04-Projects/<slug>/` |
| Concept / idea | `Toolkit/<slug>.md` |
| Ambiguous | `05-Arcs/<slug>_arc.md` (default) |

Stubs with `status: stub` are surfaced as a backlog item in `launch-brief.py`.
Unresolved links in the manifest ARE the documentation backlog — no separate
task list needed.

## Engine Behavior

### At session start

1. Load `10-System/context-manifest.md` (always — replaces hopper + full arc injection)
2. Parse all `[[terms]]` and build a resolution map
3. Do not read linked files yet
4. Note any unresolved terms — offer stub creation only if the term is used
   in conversation, not proactively

### During session

When a bracketed entity becomes topically relevant:
- Read its file silently
- Do not announce "I am now reading [[X]]" unless the user asked for it
- Use the content to inform the response naturally

When a new `[[term]]` appears in something the user writes or dictates:
- Resolve or stub per the rules above
- If stubbed, say so once

### At session close

`session-close.py` prompts: *"Any manifest updates? New entities, closed arcs,
changed focus?"* The human edits or confirms. The manifest is human-authored —
the engine never rewrites it autonomously.

## Naming Compliance Requirements

For `[[natural language links]]` to resolve reliably, every file in the vault
that the manifest will reference must satisfy:

1. **Short canonical title** — `title:` in frontmatter should be the natural
   language term you would use in a sentence. No em-dash descriptions.
   - ✓ `title: "BinaryRanch Arc"`
   - ✗ `title: "T-Mobile Breach — Service Termination After Explicit Promise"`
   - Fix: `title: "T-Mobile Breach"` + move description to body

2. **Person arcs named for the person** — `[[Alicia Andes]]` must resolve.
   Add `aliases: [Alicia Andes]` or rename the file.

3. **No special characters in titles** — avoid `+`, `.me`, `—`, `&` in the
   canonical title. Use a clean slug; put the full name in the description.

4. **`slug:` field present** — provides an unambiguous second lookup key.

## What This Replaces

| Old mechanism | Replaced by |
|--------------|------------|
| Full arc files injected at session start | `[[arc name]]` in manifest — pulled on demand |
| `hopper-events.log` full injection | Summary line in manifest + `[[Hopper]]` link |
| `last-session-brief.md` verbatim injection | Manifest updated at close with current focus |
| 18-arc dump in launch-brief | Top 3 recent arcs listed; rest are in manifest |
