# Servetus Vault Search Protocol

## Purpose

The `obsidian` CLI is the primary research tool for all vault lookups. Before asking
the user a question whose answer may already exist in the vault, run the relevant
search. This is not optional — it is the research prerequisite.

## Installation

```
/Applications/Obsidian.app/Contents/MacOS/obsidian
```

Available as `obsidian` in shell (aliased or on PATH). Version: 1.12.4+

## Vault Configuration

| Vault name | Path | Notes |
|------------|------|-------|
| `Obsidian` | `~/Nextcloud/Obsidian` | Active vault — encompasses all sub-vaults |

All sub-vaults (`Servetus/`, `Personal/`, `Ops_BinaryRanch/`, `Ops_SevenTalents/`,
`Inbox/`) are folders within the single `Obsidian` vault. Scope searches using
`path=Servetus/05-Arcs` etc.

## Core Research Commands

### Full-text search
```bash
# Basic — returns matching file paths
obsidian search query="<term>"

# Scoped to a folder
obsidian search query="<term>" path=Servetus/05-Arcs

# With JSON output
obsidian search query="<term>" format=json

# With surrounding context (requires Obsidian app to be frontmost)
obsidian search:context query="<term>"
```

### Backlinks — what connects to a file
```bash
obsidian backlinks file="way-return_arc" format=json
obsidian backlinks file="biography_arc" counts format=json
```

### Tags
```bash
# All tags with counts, sorted by frequency
obsidian tags counts sort=count format=json

# Files tagged with a specific tag
obsidian search query="tag:#ministry"
```

### Frontmatter / Properties
```bash
# All property keys used across the vault
obsidian properties format=json

# Read a specific property from a file
obsidian property:read name="status" file="way-return_arc"
```

### File and link traversal
```bash
# Outgoing links from a file
obsidian links file="way-return_arc" format=json

# Files with no incoming links (orphans)
obsidian orphans

# Files with no outgoing links (dead ends)
obsidian deadends
```

### Read a file by name
```bash
# Resolves by name like a wikilink — no full path needed
obsidian read file="way-return_arc"
```

## Research Protocol (HARD RULE)

**Run before asking.** If the user raises a topic and the answer may already exist
in the vault, search first. Never ask "do you have anything about X?" when
`obsidian search query="X"` costs one tool call.

**Sequence for arc research:**
1. `obsidian search query="<subject>"` — what files mention it
2. `obsidian backlinks file="<arc>"` — what links into the arc
3. `obsidian links file="<arc>"` — what the arc references
4. `obsidian search query="<key people>"` — named individuals
5. Read the highest-signal files before asking follow-up questions

**Path scoping strategy:**

| Research goal | path= value |
|---------------|-------------|
| Arcs only | `Servetus/05-Arcs` |
| Memories only | `Servetus/02-Memories` |
| Records/transcripts | `Servetus/01-Records` |
| Artifacts | `Servetus/00-Artifacts` |
| All Servetus | `Servetus` |
| All vaults | *(omit path)* |

## Known Limitations

- `search:context` requires Obsidian app to be in the foreground; returns empty from
  background Bash calls. Use plain `search` when running headless.
- `path=` on `tags` and `properties` commands expects a file, not a folder — omit
  path for those commands and filter results manually.
- Backlinks reflect Obsidian's link index; newly created files may not appear until
  Obsidian re-indexes (typically within seconds if the app is open).
