# Servetus Persistent Display — Always-On 1080p Screen

## Principle

Servetus is its own computer. It has its own screen. That screen is always on,
always 1080p, and always available to the human overseer on request — via
Nextcloud Talk screen share, without VNC, without third-party tools.

The display is Servetus's workspace. The human does not live there.
The human can look in anytime. That is the oversight model.

---

## The Screen

**Resolution:** 1920×1080 — hard cap, always.
**Type:** Virtual framebuffer (Xvfb) on gpu node — no physical monitor required.
**Always on:** Starts at boot, runs as a systemd service, never sleeps.
**Persistent:** State survives between tasks. Open tabs remain open. Sessions persist.

```
gpu node (always on)
  └── Xvfb :1 (virtual display, 1920×1080)
       └── Chromium (non-headless, logged in as servetus)
            └── Multiple tabs — persistent sessions
                 ├── Nextcloud dashboard (always open)
                 ├── Task tabs (opened as needed)
                 └── [additional tabs per task]
```

---

## Oversight Model

When the human wants to see Servetus's screen:

1. Human asks: "Show me your screen" (in Talk or CLI)
2. Servetus joins a designated Talk room (or creates a temporary one)
3. Servetus initiates screen share from its Chromium session
4. Human joins the call — sees Servetus's 1080p display in real time
5. Human can watch silently or give direction
6. When done, Servetus ends the share, posts a summary to the room

**No VNC required.** No separate viewer. No new infrastructure.
The monitoring surface is Nextcloud Talk — the same tool already in the stack.

---

## Architecture

### Virtual Display (Xvfb)

```bash
# Systemd service: servetus-display.service
Xvfb :1 -screen 0 1920x1080x24 -ac +extension GLX +render -noreset
```

Environment variable for all Servetus browser processes:
```
DISPLAY=:1
```

### Chromium (persistent, logged in)

Chromium runs on `:1` with a persistent profile directory:
```
~/.servetus_chromium/
  └── Default/          ← profile with saved session, cookies, tabs
```

Starts at boot. Logged into Nextcloud as `servetus`. Tabs restored on restart.

### Screen Share into Talk

Playwright (or a dedicated script) can initiate a Talk call and share the
`:1` display using the WebRTC screen capture API. Alternatively, a lightweight
script uses `ffmpeg` to stream the Xvfb framebuffer into a Talk call.

```
Xvfb :1 → ffmpeg captures framebuffer → WebRTC stream → Talk call
```

## What This Is Not

- Not a remote desktop for the human (that's RustDesk/VNC — separate)
- Not surveillance of the human's screen (Rule 8 — absolute prohibition)
- Not a shared workspace (Servetus's display, Servetus's session only)
- Not dependent on a physical monitor

---

## Hardware Note (gpu node)

gpu node runs Linux Mint 22.3. It has:
- GPU with display output (physical display optional)
- Xvfb available via `apt install xvfb`
- Chromium available via `apt install chromium-browser`
- X11 environment (required for non-headless Chromium)

Xvfb does not require the physical GPU — it runs a pure software framebuffer.
The GPU remains dedicated to Whisper/Ollama workloads.
