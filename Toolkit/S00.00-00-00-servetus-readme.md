# Servetus README (Root Key)

## Purpose
This file is the **semantic key** for the Servetus Project Kit: naming, precedence, and how the assistant should consult kit files.

## Guard Clause (Read Scope)
This README is authoritative **only** for files sharing the same first five characters: `S00.00`.

- README-to-README chains are allowed **only within the same `Sxx.xx` prefix**.
- No assumptions, mappings, or semantics should be imported across version boundaries unless explicitly stated in the new version’s root README.

## Naming Grammar
Canonical filename pattern:

`S<version>-<priority>-<subpriority>-<descriptor>.md`

Example:
- `S00.01-01-10-servetus-topic-segmentation.md`

### Fields
- `S<version>`: Servetus system version (e.g., `S00.01`)
- `<priority>`: authority tier (two digits)
- `<subpriority>`: ordering slot inside the tier (two digits)
- `<descriptor>`: kebab-case meaning (stable)

Version tracking is handled in frontmatter (`system_version`), not filenames.

## Authority & Precedence (Priority Tiers)
Lower priority number wins when conflicts exist.

- `00–09`  **Authority** (law)
- `10–19`  **Project Defaults**
- `20–29`  **Overrides**
- `90–99`  **Reference / Archives** (never authoritative)

## Recommended Kit Contents (MVP)
Authority:
- Bootloader
- Export rules
- Front matter schema
- Time rules
- Spelling rules
- Topic segmentation rules
- Sorting/placement protocol

Project defaults:
- Project index
- Project tags

Overrides:
- Overrides switches

## Portability Note
This kit is designed to be vendor-agnostic:
- Works in any environment with “project files” / “repo context”
- Does not rely on opaque memory
- Keeps rules inspectable and versionable
