# Servetus Naming Convention for Engine Integrations

**Status:** Active (decisions from 2026-06-01 tmux control room session incorporated 2026-06-02; see 2026-06-02-grok-build-hermes-usage-strategy work)

## Core Principle

Different concrete deployments and harness integrations of Servetus are named with a clear, consistent suffix so that:

- Humans can instantly know which variant is running.
- Scripts, launchers, profiles, and documentation stay unambiguous.
- The sovereign "Servetus" concept remains the common root.

## Recommended Naming Pattern

**Base name:** `Servetus`

**Suffix format:** `Servetus-<ShortCode>`

### Current Variants

| Name          | Full Meaning                          | Harness / Engine                  | Notes |
|---------------|---------------------------------------|-----------------------------------|-------|
| Servetus      | Full tmux multiviewer suite           | Hermes control + agent panes     | The primary launcher. Boots tmux with Hermes in the Control pane. |
| Servetus-C    | Servetus + Claude Code                | Direct Claude Code, no tmux      | Anthropic direct. Also aliased as Servetus-A. |
| Servetus-H    | Servetus + Hermes                     | Hermes harness, no tmux          | Single-pane Hermes with servetus profile + boot skill. |
| Servetus-G    | Servetus + Grok Build                 | Grok Build TUI, no tmux          | Uses Grok's native plan mode + subagents. |
| Servetus-O    | Servetus + Ollama                     | Ollama, no tmux                  | Free bulk / background tier. |

### Suffix Rules

- **Preferred:** 1–3 uppercase letters (or short memorable string).
  - Single letter is acceptable for the core four (C, H, G, O) because they are high-frequency.
  - Two or three letters when needed for clarity (e.g. `Servetus-Grok` or `Servetus-Llama` if we add more).
- Keep it short for command-line use (`sg`, `sh`, `sc`, `so`).
- The base word "Servetus" is **never** abbreviated.

### Launcher / Command Naming

All variants are unified in a single `servetus` script. Short and long flags are supported.
Thin wrappers (`servetus-c`, `servetus-h`, etc.) exist for convenience.

| Command | Flag | What it does |
|---|---|---|
| `servetus` | (none) | Full launch: tmux session, menu, brief, Hermes |
| `servetus -c` | `--claude` | Claude Code only, no tmux |
| `servetus -a` | (alias) | Same as `-c` (A for Anthropic) |
| `servetus -h` | `--hermes` | Hermes only, no tmux |
| `servetus -g` | `--grok` | Grok only, no tmux |
| `servetus -o` | `--ollama` | Ollama only, no tmux |
| `servetus -m` | `--attach` | Attach to existing Servetus tmux session |
| `servetus -p` | `--preflight` | Run launch brief + system checks, no engine |
| `servetus -u` | `--update` | Pull latest vault + reinstall launcher |

### Environment Variable

Use `SERVETUS_VARIANT=Servetus-G` (or the short code) when a script or process needs to know which integration it is running under. This is in addition to (or instead of) `SERVETUS_ROOM`.

### File / Directory Naming

- Inbox lanes: `Inbox/Grok/`, `Inbox/Hermes/`, `Inbox/Claude/`, `Inbox/Ollama/`
- Capture scripts: `grok-session-export.py`, future `hermes-session-close.py`, etc.
- Profiles / skills: `servetus-g`, `servetus-h`, etc.

## Rationale for Two-Character Preference

Single letters are concise but become opaque as the number of integrations grows. Two characters (G for Grok, H for Hermes, C for Claude Code, O for Ollama) strike the best balance between brevity and readability while still allowing easy command-line aliases.

Three+ characters should be reserved for less common or experimental integrations.

## Future Extensions

When we add new engines or deployment models (e.g. a dedicated "Binary Ranch hosted" variant, a web-only surface, a mobile companion, the Servetus Cortex layer, etc.), we will extend this table using the same pattern.

**Note on the Cortex (added 2026-05-31):** The Cortex is a cross-harness coordination layer, not a new engine or harness. It will be designed as per-tenant components (one Cortex view/partition per user or controlled organizational persona) in accordance with Guardrails Rule 10 and the isolation catalog (`10-System/dev-backlog/2026-05-31-isolation-mechanisms-catalog.md`).

The root authority remains the Servetus Constitution. All these variants are different *delivery vehicles* for the same sovereign system.
