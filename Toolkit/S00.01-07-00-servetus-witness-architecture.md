# Servetus Witness Architecture — Two Layers

## The Core Distinction

Two witness layers. Two vaults. Neither replaces the other.

| Layer | Vault | Grounded in | Written by |
|-------|-------|-------------|------------|
| **Owner's witness** | Owner's vault (`08-Witnesses/`) | Owner's relationship with the person | Owner + Servetus on owner's behalf |
| **Servetus's witness** | Servetus's vault (`08-Witnesses/`) | Servetus's direct interactions with the person | Servetus autonomously |

They are complementary records of the same person. They never merge. Origin is permanent.

---

## Owner's Witness File

**Path:** `08-Witnesses/<actor_id>_witness.md`
**Vault:** Owner's Obsidian vault

This file is the **relationship record**. It carries the owner's history with the person, the arc of the relationship, and the owner's own read — supplemented by Servetus's observations delivered as counsel.

## Servetus's Witness File

**Path:** `08-Witnesses/<actor_id>_witness.md`
**Vault:** Servetus's vault

This file is the **interaction record**. Built entirely from what the person said to Servetus, how they said it, what they shared. No relationship history. No arc. Pure observation.

```yaml
---

  schema_version: 2
  record_type: witness
  pipeline_stage: distilled
```

## How the Two Layers Work Together

```
Person sends a message to Servetus
    ↓
Servetus logs the conversation  →  Servetus's vault (talk log)
Servetus updates its witness    →  Servetus's vault (interaction record)
Servetus forms its assessment   →  Servetus's witness (private opinion)
Servetus delivers counsel       →  Owner's witness ("Servetus's Read" section)
                                →  Owner's Talk room (if flagworthy)
    ↓
Owner reads both layers when they want the full picture
Owner's own read stays in owner's witness file
```

The two files are linked by `owner_witness:` in Servetus's file. Never merged. Always traceable. Origin permanent.

---

## What Never Crosses Between Vaults

- Owner's personal assessment stays in owner's vault
- Servetus's private formation of opinion stays in Servetus's vault
- Artifacts stay where they were received:
  - Owner's hopper/inbox → owner's vault
  - Talk attachment sent to Servetus → Servetus's vault
- Servetus delivers **conclusions**, not raw data, to the owner's vault

The pointer (`owner_witness:`) is the bridge. Not the content.

---

## Path Configuration

Both vaults configure their paths in `config/nextcloud.env`:

```env
# Owner's vault
OWNER_VAULT=/path/to/owner/vault

# Servetus's vault
SERVETUS_VAULT=/path/to/servetus/vault
```

`vault_writer.py` routes artifacts to the correct vault based on ingestion surface:
- `surface: talk` → Servetus's vault
- `surface: hopper` or `surface: manual` → owner's vault
