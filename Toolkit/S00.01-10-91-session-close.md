# Servetus Session Close Protocol

## Purpose

A consistent end-of-day sequence that ensures nothing is left undone,
all work is recorded, and the team has a clean summary to read tomorrow.
Run this at the end of every working session, whether human-directed or autonomous.

---

## The Sequence

### 1. Commit all local changes
```bash
git status --short                     # confirm what's new
git add <files>
git commit -m "..."
```
If the GitHub deploy key is configured on workstation: `git push origin main`.

### 2. Check the transcription queue
```python
# Quick summary
cat 10-System/.transcription-queue-state.json | python3 -c "
import json, sys
state = json.load(sys.stdin)
p = state.get('processed', {})
ok = len([v for v in p.values() if v.get('status')=='ok'])
inprog = len([v for v in p.values() if v.get('status')=='in-progress'])
print(f'{ok} complete | {inprog} in-progress')
"
```
Note GPU temperature if the session was long.

### 3. Write any outstanding memories
If transcription artifacts from the day haven't been mined yet:
- Read the artifact (raw transcript)
- Extract key signals (decisions, people, projects, architectural ideas)
- Write to `02-Memories/YYYY-MM-DD-<slug>.md`
- Update any witness files with new information

### 4. Post end-of-day report to Servetus Project room
Room: `dfdps7ce` — Servetus Project

Report structure:
```
END OF DAY — Servetus | YYYY-MM-DD

━━━ TRANSCRIPTION QUEUE ━━━
[X] recordings transcribed | [Y] GPU-minutes | [Z] remaining
Range covered: [dates]
Notable sessions: [bullet list]

━━━ CODE BUILT ━━━
[list of commits with one-line descriptions]

━━━ VAULT UPDATES ━━━
[memories filed, witness updates, spec changes]

━━━ PENDING ━━━
[anything blocked or needing manual action]

— Servetus
```

### 5. Notification routing rules
| What | Where |
|------|-------|
| End-of-day report | Servetus Project (dfdps7ce) |
| Individual transcription completions | Christian 1:1 (cufo8jwd) only |
| Jim-specific recordings | Jim Coler Social (eco9ue5r) |
| High-trust action proposals | Approval room (per action config) |
| Never | Binary Ranch Standup (tnft3avs) — team room, infrastructure noise goes elsewhere |

### 6. Advance the hopper cursor
```bash
python3 10-System/secretary.py --advance
```
Marks current hopper position so tomorrow's session starts fresh.

---

## Autonomous Session Rules

When running autonomously (user away):
- Work verbosely — describe what you're doing as you do it
- Do not use background agents for primary work (everything in foreground so session is recorded)
- Post status updates to Christian's 1:1 at natural milestones
- Post end-of-day report to Servetus Project room when closing
- Do not push to GitHub without explicit permission (deploy key must be authorized first)
