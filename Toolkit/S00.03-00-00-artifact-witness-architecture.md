# Artifact/Witness Architecture

> **Status:** Draft — foundational architecture for v0.3.0+

## Core Insight

The artifact and the meaning are two separate things.

- **Artifact:** The raw file (photo, document, export, recording)
- **Witness:** The metadata wrapper (meaning, relationships, time envelope)

Separating these layers enables efficiency, portability, and interoperability.

---

## The Resource Fork Model

Like classic Mac OS resource forks:

| Component | Contains | Can Be |
|-----------|----------|--------|
| Artifact (data fork) | The actual file | Externalized, stored separately |
| Witness (resource fork) | Meaning, relationships, references | Lightweight, shareable, queryable |

The witness *references* the artifact. It doesn't contain it.

---

## Revised Altitude Model

```
00 — SYSTEM
    Toolkit specs, config, VERSION
    The operating system itself

01 — ARTIFACTS
    Raw files: photos, documents, exports, recordings
    Can be externalized to separate storage
    Referenced by hash or path

02 — WITNESSES
    Metadata wrappers for artifacts
    Time envelopes, relationships, validity
    Lightweight, human-readable

03 — DAILY-LOGS
    Stream capture, timestamped

04 — EVENTS
    Discrete moments, multiple witnesses

05 — PROJECTS
    Work clusters

06 — ARCS
    Narrative threads

07 — RADAR
    Current situational awareness

08 — STORYMAP
    30,000ft view
```

## Artifact Layer (01)

### Purpose
Store raw files without duplication or meaning-attachment.

### Characteristics
- **Content-addressable** (optional): Reference by hash for deduplication
- **Externalizable**: Can live on separate storage (NAS, cloud, archive)
- **Format-agnostic**: Any file type
- **No embedded metadata required**: Meaning lives in the witness layer

### Example Structure
```
01-artifacts/
├── 2026/
│   ├── 01/
│   │   ├── IMG_20260115_143022.jpg
│   │   ├── messenger-export-20260116.json
│   │   └── recording-20260118.m4a
│   └── 02/
│       └── ...
└── external/
    └── .pointer  # References to externalized storage
```

## Witness Layer (02)

### Purpose
Attach meaning, relationships, and time envelopes to artifacts.

### Characteristics
- **Lightweight**: Plain text Markdown + YAML frontmatter
- **References artifacts**: By path, hash, or URI
- **Portable**: Can be shared without the artifact
- **Queryable**: Structured metadata enables search/analysis

### Witness Schema

## Interoperability

### The Standard
If everyone uses the same witness schema:
- Graphs can merge where they overlap
- Timelines can corroborate across sources
- Relationships can traverse independent vaults
- No central platform required

### Permission Layers
You decide what integrates:

| Level | Shares |
|-------|--------|
| Isolated | Nothing — vault is private |
| Witness only | Metadata without artifacts |
| Artifact only | Files without meaning |
| Full | Witness + artifacts |
| Selective | Specific nodes/relationships |

### The Protocol
```
Your Vault ←── standardized schema ──→ Their Vault
     │                                      │
     └────── permission-controlled ─────────┘
              integration
```

Not a platform. A protocol.

---

## Platform Independence

Because the final data store is just files:

| Layer | Independence |
|-------|--------------|
| OS | Mac, Windows, Linux — doesn't matter |
| Platform | Obsidian, VS Code, any text editor |
| Hardware | Local, NAS, cloud, air-gapped |
| LLM | Claude, GPT, Llama, local, future |

**The spec is the contract. Everything else is implementation.**

---

## Migration Path

### From Current Structure
1. Rename `01-witnesses/` → `02-witnesses/`
2. Create new `01-artifacts/`
3. Move raw files from witnesses to artifacts
4. Update witness files to reference artifacts by path
5. Update altitude numbers in remaining folders

### Backward Compatibility
- Witnesses can embed artifacts (current behavior) OR reference them
- Gradual migration supported
- No breaking changes required

---

## Design Principles

1. **Separation of concerns** — Data and meaning are independent layers
2. **Lightweight witnesses** — Metadata travels easily; heavy files don't have to
3. **Reference, don't embed** — Witnesses point to artifacts, don't contain them
4. **Interoperable by default** — Standard schema enables graph integration
5. **Permission at every level** — You control what crosses boundaries
6. **Platform-agnostic** — Files are files; the spec is the contract

---

## Future Considerations

- **Content-addressable storage**: Reference artifacts by hash for deduplication
- **Distributed witnesses**: Share witnesses across vaults with sync
- **Witness signing**: Cryptographic proof of witness authenticity
- **Cross-vault queries**: Federated search across permissioned graphs
