# Servetus Event Definition Spec

## Origin

This spec emerged from a session observation (2026-03-27): looking at the T-Mobile
arc timeline, the large dead zone between December 2024 and January 2026 raised the
question of how Servetus should represent long stretches of time where nothing
recorded was happening — versus concentrated periods of intense activity. The
answer required a formal definition of what an **event** is.

---

## The Four-Layer Model

```
Arc
  └── Project  (optional — not all arcs have formal projects)
        └── Event  ←  atomic unit of lived experience
              └── Memory / Recording / Artifact
```

Each layer has a distinct character and time scale.

---

## Layer Definitions

### Arc

A **topic that persists across time** — a situation, relationship, dispute, creative
work, or pursuit that cannot be captured in a single event or project.

- Has no fixed end date at creation — it closes when the situation resolves
- Groups events by shared subject, not by calendar proximity
- Is the highest navigable unit in the Servetus timeline
- Examples: T-Mobile Breach, Biography, OpenClaw Competitor Intelligence, The Move

---

### Project

A **goal-oriented grouping** within an arc — optional. Use a project when an arc
contains multiple parallel streams that need their own tracking.

- Has deliverables and a finish condition
- Multiple projects can run inside one arc simultaneously
- Examples: within a "Relocation" arc — Packing Project, Sale Project, Setup Project

---

### Event

A **bounded period of continuous effort toward a shared context**, separated from
the next by a meaningful break or shift.

**The working definition (verbatim from Christian Sass, 2026-03-27):**

> *"Events are a series of recordings that can last for multiple days, series of
> memories that encompass a trip. Requires planning, something you put on your
> calendar, generally separated by some separate event that you would put on your
> calendar. It could be the same thing — it's a monthly meeting, but that's an
> event. It's one day; that's an event. An event can be multi-week. Right now,
> this situation with me being in Quincy with my wife is an event. When I am home,
> it is over. If we decide to move, the event will be from the day we start packing
> to the day we are done unpacking; that is the move."*

**Formal criteria — an event:**

1. Has a **start** and a **stop**, even if fuzzy at time of creation
2. Is something you could place on a calendar — even retroactively
3. Represents **continuous or concentrated effort** toward a single context
4. Ends when that context closes — trip returns, meeting adjourns, project completes
5. Can span hours, days, or weeks — duration is not the distinguishing factor
6. Is **separated** from adjacent events by a meaningful gap or context shift

**Boundary rule:** When there is a large gap between two dated entries inside an
arc, that gap is represented in the arc's timeline as a summary note — not as an
event. Events contain activity; gaps between events do not.

**Examples:**

| Event | Duration | Closes when |
|-------|----------|-------------|
| T-Mobile setup (Dec 7, 2024) | 1 day | Left the store |
| Jan 17 payment visit | ~2 hrs | Drove home |
| Jan 21 Carpenter meeting | ~1 hr | Call ended |
| Feb 3 equipment return | ~1 hr | Left Hoffman Estates |
| Mar 14 carrier lock day | ~4 hrs | Left QCY T-Mobile |
| Mar 16 escalation (call + store + trespass) | ~6 hrs | Got home |
| Current Quincy stay | multi-day | Return home |
| The Move (hypothetical) | weeks | Done unpacking |
| Monthly board meeting | 1 day | Meeting adjourns |

---

### Memory / Artifact

The smallest unit — a **single capture** inside an event.

- A recording (audio, video, screen capture)
- A photograph or document scan
- An atomic note (one idea, one observation)
- A transcript
- A financial record

Memories and artifacts belong to events. Events belong to projects or arcs directly.

---

## The Gap Rule — Large Time Spans in Arc Timelines

When an arc canvas or timeline shows a long gap between events, that gap is
represented as a **summary band**, not as a series of empty events.

**The T-Mobile arc dead zone** is the model:
- 13 months of service (Dec 2024 – Jan 2026): no recorded events
- Represented on the canvas as a compressed band labeled "2025 — Account Active ·
  Bills Accumulating (13 months)"
- The band is a fact about the arc, not an event

**Rule:** If the gap between two events is longer than the events themselves, and
nothing recordable happened during it, the gap gets a summary label and compressed
scale — not fabricated events.

---

## Canvas Hierarchy

This model maps directly to the Servetus canvas hierarchy:

```
StoryMap.canvas           ←  all active arcs, zoomed out
  └── [file node] → arc-name_timeline.canvas    ←  arc level
        └── [file node] → YYYY-MM-DD_event.canvas  ←  event deep-dive
```

Each level opens the next. The arc canvas contains events as nodes; clicking a
complex event opens its own canvas with recordings, artifacts, and witnesses
specific to that event.

**When to create an event-level canvas:**
- The event has 3+ recordings
- The event spans multiple days with distinct sub-sessions
- The event is a legal or evidentiary anchor (e.g., the March 16 store incident)

**When a text node on the arc canvas is sufficient:**
- Single-session event
- 1–2 artifacts that fit in the evidence lane
- No sub-structure needed
