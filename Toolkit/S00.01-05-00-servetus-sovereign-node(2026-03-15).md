# S00.01-05-00 — Servetus Sovereign Node

## Purpose

This spec defines the architecture for a **sovereign compute node** — a self-contained VM (or bare-metal install) that runs Obsidian with CLI, a local LLM, and Nextcloud sync as a single deployable unit. It is the first physical instantiation of the Servetus principle: the system outlives any particular AI, any particular service, any particular machine.

The node serves three purposes:

1. **Always-on vault operations.** Search, indexing, backlink traversal, template expansion — powered by Obsidian's runtime, available via CLI, zero tokens burned.
2. **Local intelligence.** A local LLM handles classification, summarization, intent parsing, and routine queries without any data leaving the box.
3. **Sovereign-tier runtime.** Witnesses, daily logs, radar — all Sovereign-tier data — are processed on hardware you own. The trust tier model stops being a policy you enforce and becomes an architectural fact.

The secondary goal: make this **portable and reproducible**. The VM image is a file. Copy it to new hardware, point Nextcloud at the vault, boot it up — you're back. The vault is the durable thing. The node is disposable infrastructure.

### Why a VM

Obsidian is an Electron app. It expects a display — a window manager, a compositor, a screen to render to. Running it headless requires workarounds (Xvfb, virtual framebuffers) that are fragile and break on updates.

A VM solves this cleanly. Obsidian gets a real display because the VM has one. The VM can run on any host — a desktop, a NUC, a laptop, a rack server. The guest doesn't care what the host is. The host doesn't care what the guest does.

A VM also gives you:
- **Snapshots.** Roll back if something breaks.
- **Portability.** Export the image, move it to another machine.
- **Isolation.** The node's dependencies don't conflict with the host OS.
- **Reproducibility.** Build once, deploy many times.

## VM Build Specification

### Base Image

| Component | Choice | Rationale |
|-----------|--------|-----------|
| **OS** | Debian 12 (Bookworm) or Ubuntu 24.04 LTS | Stable, long-term support, wide hardware compatibility |
| **Desktop** | XFCE4 | Lightest full desktop. Obsidian needs a window manager, not a compositor. ~200MB RAM |
| **Display** | 1280x800 minimum | Obsidian needs enough screen to render. Doesn't need to be pretty |
| **VM Type** | QEMU/KVM (Linux host) or VirtualBox (any host) | KVM for performance on Linux, VirtualBox for cross-platform |
| **Disk** | 64 GB minimum, 128 GB recommended | Vault + Obsidian + LLM models + room to breathe |
| **RAM** | 16 GB minimum, 32 GB recommended | 8B model needs ~6 GB, Obsidian needs ~1 GB, OS + headroom |

### Resource Allocation

```yaml
vm:
  cpu_cores: 4                    # Minimum. 8 recommended for LLM inference
  ram_gb: 16                      # Minimum. 32 for larger models
  disk_gb: 128                    # Vault + models + OS
  gpu_passthrough: optional       # See GPU section below
  network: bridged                # Node needs network access for Nextcloud sync
  audio: disabled                 # Voice pipeline runs on capture device, not the node
```

### GPU Passthrough (Optional)

If the host has a dedicated GPU, it can be passed through to the VM for faster LLM inference:

| Host GPU | Passthrough Method | LLM Benefit |
|----------|-------------------|-------------|
| NVIDIA (desktop) | VFIO/IOMMU passthrough | Full CUDA acceleration. 10-20x faster than CPU |
| AMD (desktop) | VFIO/IOMMU passthrough | ROCm acceleration where supported |
| Intel integrated | GVT-g (shared) | Minimal LLM benefit, sufficient for display |
| Apple Silicon | Not applicable | Use bare metal, not VM — unified memory is the advantage |

**GPU is not required.** CPU inference on a modern chip (Ryzen 5/7, i5/i7, 12th gen+) runs a 7B Q4 model at 10-20 tokens/second. That's fast enough for vault operations where you're doing short queries, not long conversations.

## Obsidian CLI Integration Layer

The key architectural decision: **never call Obsidian CLI directly from application code.** Instead, wrap it in a layer that falls back to raw file I/O when Obsidian isn't running.

### Wrapper: `00-system/node/vault_ops.py`

```python
"""
Vault operations abstraction layer.

Uses Obsidian CLI when available (indexed search, template expansion,
link-aware moves). Falls back to raw file I/O when Obsidian is not running.

The vault works either way. Obsidian is an accelerator, not a dependency.
"""

import subprocess
import shutil
from pathlib import Path

class VaultOps:
    def __init__(self, vault_path: str = "~/Servetus"):
        self.vault = Path(vault_path).expanduser()
        self._obsidian_available = None

    @property
    def obsidian_available(self) -> bool:
        """Check if Obsidian CLI is reachable."""
        if self._obsidian_available is None:
            try:
                subprocess.run(
                    ["obsidian", "version"],
                    capture_output=True, timeout=5
                )
                self._obsidian_available = True
            except (FileNotFoundError, subprocess.TimeoutExpired):
                self._obsidian_available = False
        return self._obsidian_available

    def search(self, query: str, limit: int = 10) -> list[dict]:
        """
        Search the vault. Uses Obsidian's index when available,
        falls back to ripgrep.
        """
        if self.obsidian_available:
            result = subprocess.run(
                ["obsidian", "search", f'query="{query}"', f"limit={limit}"],
                capture_output=True, text=True
            )
            return self._parse_obsidian_search(result.stdout)
        else:
            # Fallback: ripgrep
            result = subprocess.run(
                ["rg", "--json", "-l", query, str(self.vault)],
                capture_output=True, text=True
            )
            return self._parse_rg_results(result.stdout, limit)

    def read(self, note_name: str) -> str:
        """Read a note's content."""
        if self.obsidian_available:
            result = subprocess.run(
                ["obsidian", "read", f'file="{note_name}"'],
                capture_output=True, text=True
            )
            return result.stdout
        else:
            # Fallback: find and read the file
            matches = list(self.vault.rglob(f"*{note_name}*"))
            if matches:
                return matches[0].read_text()
            return ""

    def create(self, name: str, content: str = "",
               template: str = "", folder: str = "") -> Path:
        """
        Create a new note. Uses Obsidian template engine when available,
        falls back to raw file creation with manual template expansion.
        """
        if self.obsidian_available and template:
            cmd = ["obsidian", "create", f'name="{name}"', "silent"]
            if template:
                cmd.append(f'template="{template}"')
            if content:
                cmd.append(f'content="{content}"')
            subprocess.run(cmd, capture_output=True)
            # Obsidian handles template variables ({{date}}, {{title}}, etc.)
        else:
            # Fallback: manual creation
            target = self.vault / folder / f"{name}.md" if folder else self.vault / f"{name}.md"
            target.parent.mkdir(parents=True, exist_ok=True)
            if template:
                tmpl_path = self.vault / "templates" / f"{template}.md"
                if tmpl_path.exists():
                    content = tmpl_path.read_text()
                    # Manual template variable expansion
                    from datetime import datetime
                    now = datetime.now()
                    content = content.replace("{{date}}", now.strftime("%Y-%m-%d"))
                    content = content.replace("{{title}}", name)
                    content = content.replace("{{time}}", now.strftime("%H:%M"))
            target.write_text(content)
            return target

    def append(self, note_name: str, content: str):
        """Append content to an existing note."""
        if self.obsidian_available:
            subprocess.run(
                ["obsidian", "append", f'file="{note_name}"',
                 f'content="{content}"'],
                capture_output=True
            )
        else:
            matches = list(self.vault.rglob(f"*{note_name}*"))
            if matches:
                with open(matches[0], "a") as f:
                    f.write(f"\n{content}")

    def daily_read(self) -> str:
        """Read today's daily note."""
        if self.obsidian_available:
            result = subprocess.run(
                ["obsidian", "daily:read"],
                capture_output=True, text=True
            )
            return result.stdout
        else:
            from datetime import datetime
            today = datetime.now().strftime("%Y-%m-%d")
            daily = self.vault / "02-daily-logs" / f"{today}.md"
            return daily.read_text() if daily.exists() else ""

    def daily_append(self, content: str):
        """Append to today's daily note."""
        if self.obsidian_available:
            subprocess.run(
                ["obsidian", "daily:append", f'content="{content}"'],
                capture_output=True
            )
        else:
            from datetime import datetime
            today = datetime.now().strftime("%Y-%m-%d")
            daily = self.vault / "02-daily-logs" / f"{today}.md"
            with open(daily, "a") as f:
                f.write(f"\n{content}")

    def backlinks(self, note_name: str) -> list[str]:
        """Find all notes that link to a given note."""
        if self.obsidian_available:
            result = subprocess.run(
                ["obsidian", "backlinks", f'file="{note_name}"'],
                capture_output=True, text=True
            )
            return result.stdout.strip().split("\n")
        else:
            # Fallback: grep for [[note_name]] across vault
            result = subprocess.run(
                ["rg", "-l", f"\\[\\[{note_name}", str(self.vault)],
                capture_output=True, text=True
            )
            return result.stdout.strip().split("\n")

    def set_property(self, note_name: str, key: str, value: str):
        """Set a frontmatter property on a note."""
        if self.obsidian_available:
            subprocess.run(
                ["obsidian", "property:set",
                 f'name="{key}"', f'value="{value}"',
                 f'file="{note_name}"'],
                capture_output=True
            )
        else:
            # Fallback: parse YAML frontmatter and modify
            # This is significantly more complex — the Obsidian CLI
            # earns its keep here
            raise NotImplementedError(
                "Frontmatter editing without Obsidian CLI requires "
                "a YAML parser. Use the node for property operations."
            )

    def tasks(self, filter: str = "today") -> str:
        """List tasks from the vault."""
        if self.obsidian_available:
            result = subprocess.run(
                ["obsidian", "tasks", filter],
                capture_output=True, text=True
            )
            return result.stdout
        else:
            # Fallback: grep for checkbox patterns
            result = subprocess.run(
                ["rg", r"- \[ \]", str(self.vault), "--no-heading"],
                capture_output=True, text=True
            )
            return result.stdout

    def _parse_obsidian_search(self, output: str) -> list[dict]:
        """Parse Obsidian CLI search output into structured results."""
        results = []
        for line in output.strip().split("\n"):
            if line:
                results.append({"path": line.strip()})
        return results

    def _parse_rg_results(self, output: str, limit: int) -> list[dict]:
        """Parse ripgrep JSON output into structured results."""
        import json
        results = []
        for line in output.strip().split("\n"):
            if line:
                try:
                    data = json.loads(line)
                    if data.get("type") == "match":
                        results.append({"path": data["data"]["path"]["text"]})
                except json.JSONDecodeError:
                    results.append({"path": line.strip()})
        return results[:limit]
```

## Multi-Node Mesh (Aspirational)

This section documents a **design target**, not a proven architecture. The individual pieces exist. Whether gluing them together is worth the complexity is an open question.

### The Vision

Multiple sovereign nodes — each with different hardware capabilities — discover each other on a network, advertise their resources, and collaborate on tasks. You carry a laptop node. Your desk has a GPU node. A NUC sits on a shelf at home. They all share the same vault via Nextcloud and route work to the best-equipped node.

```
┌─────────────────────────────────────────────────────────────────┐
│                        MESH NETWORK                              │
│                    (LAN / VPN / ZeroTier)                  │
│                                                                  │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────┐  │
│  │  NODE A       │  │  NODE B       │  │  NODE C              │  │
│  │  Laptop       │  │  Desktop      │  │  NUC (always-on)     │  │
│  │               │  │               │  │                      │  │
│  │  CPU: Ryzen 7 │  │  CPU: i7      │  │  CPU: N100           │  │
│  │  RAM: 32 GB   │  │  RAM: 64 GB   │  │  RAM: 16 GB          │  │
│  │  GPU: none    │  │  GPU: 3080    │  │  GPU: none            │  │
```

### Work Routing

When a task arrives (from the bot service, a CLI command, a cron job), the mesh decides which node handles it:

```
Task: "Summarize this 50-page transcript"
  Requirement: LLM with large context window

  Node A (laptop, CPU only):  Can do it. ~5 minutes. Battery impact.
  Node B (desktop, 3080):     Can do it. ~30 seconds. Plugged in.
  Node C (NUC, N100):         Can do it. ~15 minutes. Always on.

  Decision: Route to Node B (fastest, no battery concern).
  Fallback: Node C (if B is offline — slower but always available).
```

#### Routing Rules

```yaml
mesh:
  routing:
    # Prefer GPU nodes for LLM tasks
    llm_preference: [gpu, high_ram, any]

    # Prefer always-on nodes for scheduled tasks
    cron_preference: [always_on, any]

    # Prefer the node you're physically at for interactive tasks
    interactive_preference: [local, fastest, any]

    # Never route Sovereign-tier data outside the mesh
    trust_constraint: sovereign_only

    # If no node is available, queue the task (don't drop it)
    offline_behavior: queue
```

### Hard Problems (Unsolved)

These are the reasons this section is aspirational:

**1. Vault consistency.** Nextcloud sync is eventually consistent, not instantly consistent. If Node A creates a file and Node B searches 2 seconds later, the file might not be there yet. Solutions exist (sync callbacks, polling, shared filesystem instead of sync) but add complexity.

**2. LLM state.** If Node A starts a conversation and Node B picks it up, the context is lost. Ollama doesn't have session sharing across instances. You'd need to serialize conversation state to the vault and reload it — possible but adds latency.

**3. Discovery across networks.** mDNS works on a LAN. If your laptop is on coffee-shop wifi and your desktop is at home, they can't see each other. Solutions: VPN (creates a virtual LAN across the internet), ZeroTier (same idea), or a lightweight coordinator service on the Nextcloud server.

**4. Security.** Nodes trusting each other on a LAN is one thing. Nodes trusting each other across the internet requires mutual authentication. VPN handles this well. Rolling your own is a minefield.

**5. Is it worth it?** A single well-spec'd node (32 GB RAM, decent CPU, maybe a GPU) handles everything Servetus currently needs. The mesh adds value when you have genuinely heterogeneous hardware and want to use all of it — but the complexity cost is real. Start with one node. Add mesh when one node isn't enough.

### Mesh Protocol (If Pursued)

If the mesh proves worthwhile, the protocol would look like:

```
1. ANNOUNCE  — Node joins network, broadcasts capabilities via mDNS
2. DISCOVER  — Nodes maintain a live roster of peers
3. HEARTBEAT — Periodic liveness check (every 30s)
4. ROUTE     — Task arrives, routing logic selects best node
5. DELEGATE  — Task sent to selected node via HTTP API
6. EXECUTE   — Selected node runs the task
7. REPORT    — Result returned to requesting node (or written to vault)
8. SYNC      — Nextcloud propagates any vault changes to all nodes
```

Each node exposes a simple HTTP API:

```
GET  /status              — Node health and capabilities
GET  /models              — Loaded LLM models
POST /task                — Submit a task for execution
GET  /task/{id}/status    — Check task progress
GET  /task/{id}/result    — Retrieve task result
```

Secured with mutual TLS or VPN's built-in auth. No custom auth layer.

## Build Script

A reproducible build for the VM image:

```bash
#!/bin/bash
# 00-system/node/build-node.sh
# Creates a sovereign node from a fresh Debian/Ubuntu install.
# Run as root or with sudo.

set -euo pipefail

NODE_USER="${1:-user}"
VAULT_PATH="/home/${NODE_USER}/Servetus"

echo "=== Servetus Sovereign Node Build ==="
echo "User: ${NODE_USER}"
echo "Vault: ${VAULT_PATH}"

# --- System packages ---
apt update && apt upgrade -y
apt install -y \
  xfce4 xfce4-terminal lightdm \
  git curl wget jq \
  python3 python3-pip python3-venv \
  ripgrep fd-find \
  openssh-server \
  avahi-daemon avahi-utils \
  nextcloud-desktop

# --- Ollama ---
if ! command -v ollama &>/dev/null; then
  curl -fsSL https://ollama.com/install.sh | sh
fi
systemctl enable ollama
systemctl start ollama

# --- Pull default model ---
sudo -u "${NODE_USER}" ollama pull llama3.1:8b-q4_K_M

# --- Obsidian (AppImage) ---
OBSIDIAN_DIR="/home/${NODE_USER}/Applications"
mkdir -p "${OBSIDIAN_DIR}"
# NOTE: Update version number as needed
OBSIDIAN_VERSION="1.12.4"
wget -O "${OBSIDIAN_DIR}/Obsidian.AppImage" \
  "https://github.com/obsidianmd/obsidian-releases/releases/download/v${OBSIDIAN_VERSION}/Obsidian-${OBSIDIAN_VERSION}.AppImage"
chmod +x "${OBSIDIAN_DIR}/Obsidian.AppImage"
chown "${NODE_USER}:${NODE_USER}" "${OBSIDIAN_DIR}/Obsidian.AppImage"

# --- Servetus vault (clone if not present) ---
if [ ! -d "${VAULT_PATH}" ]; then
  echo "Vault not found at ${VAULT_PATH}."
  echo "Either clone your repo or configure Nextcloud sync to populate it."
fi

# --- Node scripts directory ---
mkdir -p "${VAULT_PATH}/00-system/node"

# --- Autostart entry ---
mkdir -p "/home/${NODE_USER}/.config/autostart"
cat > "/home/${NODE_USER}/.config/autostart/servetus-node.desktop" << 'DESKTOP'
[Desktop Entry]
Name=Servetus Sovereign Node
Exec=/home/user/Servetus/00-system/node/start-node.sh
Type=Application
X-GNOME-Autostart-enabled=true
DESKTOP
chown "${NODE_USER}:${NODE_USER}" "/home/${NODE_USER}/.config/autostart/servetus-node.desktop"

# --- mDNS advertisement for mesh discovery ---
cat > /etc/avahi/services/servetus-node.service << 'AVAHI'
<?xml version="1.0" standalone='no'?>
<!DOCTYPE service-group SYSTEM "avahi-service.dtd">
<service-group>
  <name replace-wildcards="yes">Servetus Node on %h</name>
  <service>
    <type>_servetus._tcp</type>
    <port>8400</port>
    <txt-record>version=0.1</txt-record>
    <txt-record>role=sovereign-node</txt-record>
  </service>
</service-group>
AVAHI
systemctl restart avahi-daemon

echo "=== Build complete ==="
echo "Next steps:"
echo "  1. Reboot into XFCE desktop"
echo "  2. Launch Obsidian and open vault at ${VAULT_PATH}"
echo "  3. Enable CLI in Obsidian Settings → General → Command line interface"
echo "  4. Configure Nextcloud client to sync vault"
echo "  5. Verify: obsidian help && ollama list"
```

## Node Health Check

```bash
#!/bin/bash
# 00-system/node/health-check.sh
# Quick status check for a sovereign node.

echo "=== Servetus Node Health ==="

# Obsidian
if obsidian version >/dev/null 2>&1; then
  echo "Obsidian CLI: ✓ ($(obsidian version))"
else
  echo "Obsidian CLI: ✗ (not running or not in PATH)"
fi

# Ollama
if ollama list >/dev/null 2>&1; then
  echo "Ollama:       ✓"
  ollama list 2>/dev/null | head -5
else
  echo "Ollama:       ✗ (not running)"
fi

# Nextcloud sync
if pgrep -x nextcloud >/dev/null 2>&1 || pgrep -f "Nextcloud" >/dev/null 2>&1; then
  echo "Nextcloud:    ✓ (syncing)"
else
  echo "Nextcloud:    ✗ (not running)"
fi

# Vault
VAULT="$HOME/Servetus"
if [ -d "$VAULT" ]; then
  NOTE_COUNT=$(find "$VAULT" -name "*.md" | wc -l)
  echo "Vault:        ✓ (${NOTE_COUNT} notes at ${VAULT})"
else
  echo "Vault:        ✗ (not found at ${VAULT})"
fi

# Mesh peers
if command -v avahi-browse &>/dev/null; then
  PEERS=$(avahi-browse -t _servetus._tcp 2>/dev/null | wc -l)
  echo "Mesh peers:   ${PEERS} discovered"
fi

# System resources
echo ""
echo "--- Resources ---"
free -h | head -2
echo "CPU: $(nproc) cores, load: $(cat /proc/loadavg | cut -d' ' -f1-3)"
df -h "$VAULT" 2>/dev/null | tail -1
```

## What This Is

- **A deployable unit.** One VM image (or one build script) produces a working sovereign node.
- **A fallback-safe design.** Every Obsidian CLI operation has a raw-file fallback. The vault works without Obsidian running. Obsidian makes it faster, not possible.
- **A portable sovereignty architecture.** The node runs on a $100 NUC or a $2000 laptop. The vault is the same either way.
- **A foundation for the mesh.** Single-node is the proven base. Multi-node mesh is the aspiration. Start with one. Add more when one isn't enough.

## What This Is Not

- **Not cloud infrastructure.** No containers, no Kubernetes, no AWS. This runs on hardware you can touch.
- **Not a product.** This is a personal infrastructure spec. It works for one person's vault, not a multi-tenant service.
- **Not dependent on Obsidian.** Obsidian is an accelerator. If Obsidian disappears tomorrow, the vault is still Markdown files in folders. The fallback paths in `vault_ops.py` prove this.
